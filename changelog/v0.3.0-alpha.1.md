## v0.3.0-alpha.1 — 2026-11-06


Generated from Lingara API 2026-11-current-crayfish (development) at spec backend@eace1b3bb63d501ecc2f338770860fbf4db8b747.

### Added

- `planDialogue` in all seven libraries (ADR 3.11.26n): `POST /v1/embed/dialogue/plan`, the next beats of a Procedural dialogue (`embed:play`, a metered payer only), beside `sendDialogueTurn` and named in each language's casing (`plan_dialogue` in Rust and Ruby, `PlanDialogue` in Go). The answer is a typed fragment (`status: planned`, a `PlanFragment` of `Beat`s with their `Exit`s) or a keep (`status: kept`, a `KeptReason`); a keep is a result, never an error. Like the turn it is **never retried**: every call spends one `embed:play` unit, a keep and every refusal after admission included, so a `429` or `503` is raised at once with its `retry_after`. The libraries set no plan timeout and validate neither the document nor the fragment. The request and its parts are generated (`DialoguePlanRequest`, `PlanReason`, `VisitedBeat`, `AtomKind`); the answer is hand-written in Go, Java and Kotlin as one `DialoguePlanResponse` with `status`, `fragment` and `reason`, because their generators' `oneOf` output either imports a runtime package (Go), needs support files the build does not generate (Java) or decodes neither arm (Kotlin). Ruby and PHP return the generated arm (`DialoguePlanResponseOneOf` or `…OneOf1`), and Rust and TypeScript the generated tagged union.
- `NpcDisposition` (`suggestibility`, `initiative`, each 0–1) on the turn's `npc.disposition`, and `steer` on the turn's `checkpoint`; a `disposition` needs a `checkpoint`.
- `DialogueRule` gains `kind_mismatch`, `steer_target`, `pool_escape` and `atom_set`; `DialogueWarningCode` gains `stance_contradiction`, `steer_weak` and `schema_v2`. Every save or read of a revision stored as `dialogue.v2` carries `{code: schema_v2, path: /schema}`. `/v1/dialogues` accepts a `dialogue.v2` `definition` of either kind, passed through unchanged.
- One `planDialogue` snippet per language.

### Changed

- The libraries are generated from the `2026-10-dauntless-hoopoe` contract. Frozen versions before it carry a server-side `VersionChange` that downgrades the four new `rule` words to `bound` and drops the three new warnings, so a caller pinned to one of them never meets a word an older library lacks.
- **Breaking:** the grown `DialogueRule` and `DialogueWarningCode` are closed enums in Rust, Java, Kotlin and Ruby, as are the new `KeptReason` and `AtomKind`. An exhaustive Rust `match` (or Kotlin `when`, or Java `switch` expression) over the two grown enums stops compiling until it handles the new variants, and a reason or atom a later spec adds fails the whole answer's decode until you upgrade. Go, TypeScript and PHP keep them open.
- **Rust source break:** the generated `DialogueNpc` and `GraphCheckpoint` gain the optional `disposition` and `steer`, so a struct literal adds `disposition: None` and `steer: None`. The crate is pre-1.0.
- Ruby's `Decoding.response` decodes a `oneOf` answer through its generated arms, so a union is no longer read as a malformed response. PHP's `planDialogue` picks the arm by `status`, since its generated merged class rewrites `planned` to an unknown status.

### Fixed

- Java no longer sends an unset optional set (the turn checkpoint's `may_disclose`) as `[]`: the request mapper leaves an empty `Set` out, as it already did an empty `List` or `Map`.
